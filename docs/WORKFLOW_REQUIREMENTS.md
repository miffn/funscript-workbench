# 自动发布准备工作流需求

版本：v0.8。更新日期：2026-09-30。状态：独立预览与模型/Pitch HUD 已通过用户验收，作品详情“一键生成预览”及持久后台任务已接入；共享标签、无预览标签列表和本地历史资料的一次性标签导入已完成。完整发布准备链中的热力图、库存链接编辑与发帖正文生成仍待实现。

## 目标与入口

在作品详情点击“一键准备”，由 WSL 后端执行素材检查、预览视频、GIF、热力图及发帖草稿准备。网页显示任务进度、结果保存位置、错误并支持重试，提供“打开预览文件夹”入口，不需要打开 OFS、ScreenToGif、热力图 EXE，也不需要手动启动脚本。内部可以调用独立命令行程序。

发布状态仍只有“待发布、已发布”。生成完成不自动改成已发布。日常数据以工作台为准，不继续依赖或更新外部资料源。私有备注不进入公开发帖内容。

## 已确认的媒体规则

| 项目 | 规则 |
| --- | --- |
| 默认选段 | 原视频时长的 20%、40%、60%、80% 处，各取 10 秒 |
| 预览视频 | 四个片段分别输出四个 10 秒 WebM，1920×1080，保留原视频和脚本驱动的 3D 模拟器，去掉 OFS 编辑界面及脚本曲线 |
| GIF | 四个片段分别压制成四个 10 秒 GIF，192×108，只显示原视频画面，不包含 3D 模拟器 |
| 时间一致性 | 预览与 GIF 默认使用同一组片段；全部关联轴脚本按同一原视频绝对时间采样 |
| 多轴驱动 | 同一视频关联的不同轴脚本一起输入同一个模拟器，逐帧组合位置与旋转 |
| 生成方式 | 后端直接生成媒体文件，不进行桌面屏幕捕获 |
| 现有工具 | 复用 OFS 的模型与运动规则；热力图复用现有源码、样式及参数 |
| 成品目录 | `D:\Media\workspace\预览\<完整编号>\`；包括 WebM、GIF 和热力图 |
| 网页入口 | 显示生成进度，提供打开对应编号预览文件夹的入口；不要求实现成品在线播放页面 |

GIF 来自同一组干净的原视频片段；不能直接把已叠加模拟器的最终预览压缩为 GIF，否则会违反“只保留原视频”的要求。

## 建议采用的细化默认值（尚未逐项确认）

- 百分比表示每段的起点，例如 10 分钟视频取 02:00、04:00、06:00、08:00 起各 10 秒。
- 四段分别交付，按 20%、40%、60%、80% 对应序号 1、2、3、4。每个片段生成一份 WebM 和一份 GIF，共八个媒体文件，不拼成 40 秒文件，供用户自行挑选。
- 预览使用原视频画面叠加 3D 模拟器；默认模型为自定义 OFS 源码内置白圆柱和彩色 Twist 标记。必须保留实际关联轴数值 HUD、Stroke 位移徽标及引线；S064 的 Pitch 数值不能省略。人物 GLB 仅作可选模型。位置、占比及镜头通过样例核对。
- 预览格式已确认 WebM。建议预览默认 30 fps、GIF 默认 10 fps；GIF 使用调色板生成与压缩。预览是否保留原音频、水印及其样式尚待确认。
- 非 16:9 原视频等比例缩放并补边，固定输出画布尺寸，不拉伸画面。
- 片段越过视频结尾时向前移动起点，尽量保留 10 秒。视频不足 10 秒时只取实际长度；短视频中重叠或重复片段应去重并提示实际选段，不能补造不存在的内容。
- 自动按默认规则生成，不要求每次确认候选片段；网页支持重新生成。手动调整选段界面未确认为必需。

## 多脚本与同步规则

用户确认：一个视频关联多个轴脚本时，全部参与同一个模拟器的运动，而非只读取主轴或分别生成独立模拟器视频。

- 每帧以原视频绝对时间 t 同时采样 Stroke、Surge、Sway、Twist、Roll、Pitch 的关联脚本，再按 OFS 的规则组合平移和旋转。例如原视频 10～20 秒的片段，在第 2 秒读取所有轴脚本第 12 秒的位置。
- 脚本之间保留各自的动作时间点；某一帧按该轴的插值规则取值，不要求各文件动作时间戳相同。
- 兼容现有命名约定：`video.funscript` 对应 Stroke，`video.surge.funscript`、`video.sway.funscript`、`video.twist.funscript`、`video.roll.funscript`、`video.pitch.funscript` 对应其他轴。只有能够明确关联到当前视频的文件才进入该组，不能把作品文件夹内所有脚本混在一起。
- 同一视频、同一轴的多个版本是选择冲突，不能合并位置、累加运动或按文件遍历顺序静默覆盖。网页提示具体文件并让用户选择，保存轴与文件的关联，后续任务复用。
- 任务参数和输入指纹覆盖整个关联脚本组；任一轴脚本改变都使对应预览需要重新生成。网页与任务记录可查阅每个轴实际使用的文件。
- 缺失轴建议沿用现有 OFS 的中立值 50，不作为已存在脚本处理；损坏、空动作或覆盖区间异常的脚本在素材检查中单独提示，不静默丢弃。

## 后端设计建议

采用“工作台任务队列 + 独立无界面渲染器 + FFmpeg”，不搬入完整 OFS 编辑器。任务读取确定的视频和对应多轴脚本，按每帧的原视频时间计算运动，加载复用的模型并离屏渲染，随后为每个片段分别完成画面合成与编码。

处理链：

1. 检查作品素材、视频时长、脚本 JSON、轴文件、明确对应关系与输出参数。
2. 计算四个区间，并生成同一组原视频片段。
3. 每帧按相同绝对时间采样全部关联轴脚本，组合驱动同一个 3D 模型；每段独立合成并输出 1920×1080 WebM，共四份。
4. 将四段干净的原视频分别压制为 192×108 GIF，共四份，不加入模拟器。
5. 调用改造后的热力图模块。
6. 使用工作台元数据与生成结果准备发帖草稿，列出仍缺少的链接或必填项。

生成中间媒体时避免重复有损编码。任务记录输入文件指纹、参数、模型与工具版本、实际选段、输出路径、耗时和错误。相同输入与参数的已成功结果可复用；输入变化后应提示重新生成。失败可重试，不覆盖此前成功版本；同一作品重复点击时复用进行中的任务。

原始素材保持只读；用户明确指定的 `workspace\预览\` 是生成成品的可写例外。成品保存到对应完整编号目录；中间文件放在工作台内部数据目录，不混入供用户挑选的成品。任务记录与产物索引持久化。后台任务与发布状态分开。长任务不阻塞网页及库存扫描。

## 成品目录与打开入口

新建专用根目录 `D:\Media\workspace\预览`，其直接子级以完整编号命名。`S050`、`S050_001` 等编号分别建目录，不能去掉子编号。即使源素材位于 `2026`，成品也统一保存到此根目录。

例如 S050 的结构：

```text
D:\Media\workspace\预览\S050\
    预览视频1.webm       # 原视频 20% 起，10 秒，含 3D 模拟器
    预览视频2.webm       # 40%
    预览视频3.webm       # 60%
    预览视频4.webm       # 80%
    预览gif1.gif         # 20%，只有原视频画面
    预览gif2.gif         # 40%
    预览gif3.gif         # 60%
    预览gif4.gif         # 80%
    热力图.png           # 实际数量随现有热力图工具输出确定
```

- 网页显示任务整体进度、各步骤结果及失败信息，并提供“打开预览文件夹”按钮，打开该编号目录，用户自行挑选文件。
- 沿用已确认的主机限制：仅 D 盘素材所在 Windows 主机上的客户端可打开本机目录；其他客户端显示不支持打开。
- `workspace\预览` 整体排除出库存发现与素材扫描，不能把其中的编号目录当成新库存，也不能将这些输出回扫为源视频。
- 写入权限仅限该专用输出目录；不扩大到原视频、脚本或其他素材目录。打开入口应只接受服务端记录的生成目录，不接受任意客户端路径。
- 一个编号存在多个原视频时，需要先确定处理哪一个视频；如果未来支持全部处理，须另行明确文件命名，避免覆盖。目前不擅自追加目录层级。
