# Funscript 库存工作台需求草案

版本：v1.0。更新日期：2026年9月30日。首版核心需求已确认并完成实施；代码、部署与验证说明见项目 README 及实施记录。

工作台用于手动扫描本地已完成的脚本库存、关联视频和脚本素材，并维护发布状态。以后只在工作台维护进展，外部资料源用于一次性导入历史信息。本次修订明确：有编号文件夹的作品已经制作完成，工作台只使用“待发布、已发布”两个状态。扫描仅由网页“立即扫描”触发。

## 已确定的规则

| 项目 | 规则 |
| --- | --- |
| 库存目录 | `D:\Media\2026` 和 `D:\Media\workspace` |
| 完成库存 | 已建立编号文件夹的作品，视为制作完成 |
| 未编号素材 | workspace 中单纯放置、尚未建立编号文件夹的素材，不计入已完成库存 |
| 编号来源 | 用户自行建立文件夹，以文件夹中的编号为准 |
| 发布状态 | 仅“待发布、已发布”；不维护制作状态 |
| 合集与子编号 | 用户自行建立 `S025_001` 等完整编号文件夹，每个编号独立关联素材和发布状态 |
| 编号冲突 | 工作台检测并提醒，显示涉及的路径，供用户处理 |
| 后续维护入口 | 工作台；不继续更新外部资料源 |
| 首版自动化 | 手动触发扫描并更新素材信息 |
| 部署与访问 | 部署在 WSL 中，以网页形式通过局域网访问 |
| 持久化 | 库存关联、发布状态和人工维护信息保存在服务端，重启后保留 |
| 文件操作 | 仅素材所在 Windows 主机上的客户端支持一键打开作品文件夹；其他客户端提示不支持打开 |
| 视频展示 | 支持视频封面预览，首版无需视频播放或一键打开 OFS |

目录位置不决定发布状态，已发布作品可以仍然保留在 workspace。

## 库存条目与素材

一条库存对应一个完整的文件夹编号。`S025`、`S025_001` 和 `S025_002` 是不同编号，不能把子编号去掉后合并。用户负责建立需要的编号文件夹，工作台不自动拆分合集、生成子编号或搬运素材。

每条库存关联该文件夹中的视频、`.funscript` 及辅助素材。同一条库存可以有多个视频、多个脚本版本及多轴文件；这些文件的数量不直接等于库存数量。预览、热力图和 OFS 项目文件可作为辅助素材展示。

编号已存在但素材暂不齐全时，应显示素材缺失提示，不能将作品改为“制作中”。发布状态与素材是否齐全分开表达。

## 扫描与更新

### 核心需求

1. 点击“立即扫描”后，发现两个根目录下新增的编号作品文件夹，读取完整编号并建立库存关联。
2. 扫描作品文件夹内的素材，发现视频、脚本及辅助文件的变化。
3. 发现编号重复或关联不一致时提醒用户，不能静默覆盖已有记录。
4. 扫描更新文件信息时，保留用户在工作台维护的发布状态、标题、链接和备注。
5. 不通过文件数量、视频标题或目录位置推断已发布状态。
6. workspace 中未编号的素材不创建正式库存条目，也不分配制作状态。

### 建议采用的细化规则

- 兼容 `S064`、`S062_标题` 和 `S025_001_标题` 等命名，完整保留子编号。
- 将 `S29` 和 `S029` 识别为同一规范编号，同时保留原始文件夹名称和路径；本地已经存在这种差异。
- 同一规范编号在两个目录或多个路径出现时，将路径并列展示，不自动合并或选择其中一个。
- `Preview`、`heatmaps`、下载、剪辑和工具目录不直接作为作品库存。
- 同编号文件夹改名或在两个根目录之间移动时，保留人工维护信息；编号本身改变时提示关联变化。
- 文件缺失与根目录暂时不可访问分开显示，不能因为一次扫描失败删除库存或清空素材关联。
- 可以展示未编号素材提示，但不将其计入完成库存和待发布数量。

首版采用这些细化规则：仅通过“立即扫描”入口提交扫描，不再启动或定时扫描；已提交任务不依赖浏览器持续打开，并在服务重启后恢复。两个根目录的直接子级编号文件夹建立库存，作品内部素材递归扫描；不会根据内部视频或素材子目录自动拆分合集。

扫描目录可在设置页从已配置根目录中勾选，选择持久化到 SQLite；初始默认全部启用，至少选择一个。只有已保存选择影响后续手动扫描，保存本身不扫描；已提交任务使用自身目录快照。未选目录跳过文件读取及封面更新，原有库存、关联、标签和人工发布资料保留，不将“未选择”视为目录丢失。

## 发布状态与历史迁移

日常发布状态只有两个值。用户在工作台中维护，后续扫描不覆盖人工修改。建议新建且无历史发布依据的编号库存默认“待发布”。已发布状态来自用户确认或首次导入的历史资料，不能以位于 2026 或 workspace 为依据。

首次迁移可导入用户自行提供的本地历史资料，按完整编号关联；旧制作状态不进入工作台状态体系，导入后日常维护使用本地数据库。

导入记录按完整编号匹配本地文件夹。比如 `S025_001` 不能自动匹配到 `S025`。历史记录暂时找不到对应编号文件夹时，提示未匹配，并保留待关联资料；不据此自动建立或改名本地文件夹，也不直接增加已完成库存数量。

## 工作台页面与操作

库存列表展示编号、标题、视频与脚本关联、发布状态和素材异常。建议支持编号与标题搜索，以及待发布、已发布和编号冲突筛选。数量统计以规范化后的库存编号为单位；冲突条目另行提示，不能因重复路径重复计数。

库存详情展示素材清单、本地路径、历史发布资料，并允许修改发布状态及必要的作品信息。已发布作品仍可浏览和维护。提供视频封面预览和“打开文件夹”按钮。

### 视频封面预览

网页能够展示作品对应的视频封面。首版无需在线播放视频，也不需要提供打开 OFS 的按钮。

建议优先复用可明确关联的已有封面；无封面时从本地视频提取静态缩略图并缓存。列表展示小图，详情可查看大图；加载封面不需要浏览器下载整个视频。视频变化后刷新对应缓存，视频缺失或提取失败时显示占位图和提示，不阻塞其他库存。

一条库存含多个视频时，建议先展示一张代表封面，其余素材仍保留在清单中。封面选择与是否允许更换的规则在实现方案中细化；库存以卡片还是表格为主尚未定稿。

### 一键打开文件夹

按钮目标是打开库存记录关联的实际目录，不能只复制路径。编号冲突或多个关联路径存在时，应让用户选中具体路径，避免打开错误目录。

用户已确定：仅在存放 D 盘素材的 Windows 主机上访问工作台时支持这个按钮，打开的是这台主机的资源管理器。局域网其他电脑、手机等客户端显示“不支持打开，仅素材所在主机可用”，不尝试打开访问端目录，也不能触发素材主机上的资源管理器。其他客户端仍可正常查看库存和视频封面、维护发布状态。

建议远程客户端禁用按钮，并显示上述说明。服务端也需要判断请求是否来自支持的主机客户端；远程直接调用接口时同样返回“不支持打开”，不能只在网页上隐藏或禁用按钮。无法可靠识别访问端时按不支持处理，识别方法在实施中确定并验证。

网页服务运行在 WSL，实际目录打开由 Windows 网关调用主机资源管理器。按钮只接受已关联库存目录的标识，由服务端解析真实路径，不接受任意命令或浏览器传入的任意路径。调用失败或目录不存在时展示具体原因，不能仅因请求返回成功就声称文件夹已打开。

## 部署与持久化

### 已确定的使用要求

工作台部署在 WSL，提供局域网网页访问。前后端是否拆成独立服务不是硬性要求；用户接受便于维护的部署方式。业务数据持久化存储，不能仅存在浏览器缓存中。更换浏览器、关闭页面或重启服务后，已维护的发布状态和素材关联必须保留。

当前项目及文档保存在 WSL 的 `/home/user/projects/script-workbench`，原始 Windows 需求文档仍保留。应用使用 systemd 用户服务，Windows 网关提供本机与局域网访问入口，启停方法见 README。

### 推荐的首版实现方向

建议前端界面与后端业务逻辑分层组织，由同一个 WSL 应用服务提供构建后的页面、接口和封面图片。局域网用户只访问一个地址；后端负责扫描素材、生成封面和持久化。这样仍可独立维护页面和业务代码，部署时只维护一个应用服务。

首版使用 SQLite 保存库存编号、关联路径、发布状态、人工字段、扫描结果和封面索引，数据库放在 WSL 的 Linux 数据目录中，独立于构建产物。局域网浏览器通过 FastAPI 服务读写数据，不直接共享或打开数据库文件。

视频和脚本继续保留在现有 D 盘目录，WSL 服务通过实际的盘符挂载路径读取；不会为了网页访问把全部素材迁移进项目。封面缓存单独持久化，可以在丢失后重新生成，不能因此丢失人工维护的状态。

局域网访问需要在实施时检查 WSL 网络模式、监听地址和防火墙规则，并用另一台局域网设备实际打开页面验证。Windows 主机的 localhost 可访问不等于局域网已可访问。本次只明确局域网范围，不要求公网部署。

## 首版验收场景

| 场景 | 预期结果 |
| --- | --- |
| 新建 `workspace\S069_标题` 文件夹 | 点击“立即扫描”后识别 S069，并关联该文件夹素材；没有制作状态 |
| 在 workspace 根目录单纯放入未编号视频 | 不建立正式库存，不增加已完成库存数量 |
| 分别建立 `S025_001` 和 `S025_002` 文件夹 | 显示为两个独立编号，各自关联素材和发布状态 |
| 一个文件夹增加主脚本与 pitch、roll 等轴文件 | 素材列表更新，库存条目数量不因轴文件增加 |
| 导入历史状态 | 仅按完整编号关联，保留人工修改 |
| 同一编号在多个路径出现 | 显示冲突编号和所有涉及路径，供用户处理 |
| 人工将某库存改为已发布后再次扫描 | 保留已发布状态及人工维护的信息 |
| 旧表存在 `S025_001`，本地只有 `S025` | 提示未匹配，不自动关联到 S025 或改动目录 |
| 历史导入完成后停止维护外部资料源 | 工作台仍能独立维护发布状态 |
| 修改发布状态后关闭网页并重启服务 | 状态、作品字段及关联信息仍然保留 |
| 使用另一个浏览器访问同一服务 | 读取相同的服务端库存与状态 |
| 从另一台局域网设备访问 | 网页、库存接口和视频封面均能正常加载 |
| 在素材所在 Windows 主机上点击打开文件夹 | 这台主机的资源管理器打开该库存对应的 D 盘目录 |
| 从其他电脑或手机访问打开文件夹功能 | 显示不支持提示，不在访问端或素材主机上打开目录；其他库存功能仍可使用 |
| 远程客户端直接调用打开目录接口 | 返回不支持，不触发 Windows 资源管理器 |
| 本机点击打开已不存在的库存目录 | 提示目录不存在，不打开错误目录，也不改变发布状态 |
| 无现成封面但视频可读取 | 根据最终选定规则生成封面，并在后续浏览时复用缓存 |
| 视频缺失或封面提取失败 | 显示占位与异常信息，其他库存仍可浏览 |

上述场景用于定义预期行为，尚未实施或运行软件测试。建议规则的验收细节在后续对齐时补充。

## 实施细节与后续扩展

核心范围已确定：手动扫描、库存关联、两种发布状态、历史导入、视频封面、主机限定的目录打开，以及 WSL 局域网网页访问和持久化。

扫描频率、封面选取、主机客户端识别和页面布局由后续实现方案细化，不再增加制作状态或合集自动拆分逻辑。技术方案当前建议采用单个 WSL 应用服务与 SQLite。

前后端职责、数据对象、接口草案和视觉方向已整理到 [前后端设计方案](DESIGN.md)，其中技术选型和页面布局仍为评审建议。

预览视频生成、热力图生成、发帖准备等其他自动化暂作为后续扩展，未纳入首版。当前已确定的自动化是库存扫描。
