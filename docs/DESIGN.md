# Funscript 工作台前后端设计方案

更新日期：2026年9月30日。状态：用户已批准，首版已实施并部署。实际部署入口和验证结果以项目 README 与实施记录为准。

方案基于 [需求文档](REQUIREMENTS.md)。推荐前后端按职责分开组织，开发时独立运行，生产部署时由一个 WSL 服务同时提供网页与 API。前端采用封面画廊为主的库存界面，后端维护真实库存、发布状态和主机操作。

## 技术选型建议

| 层 | 建议 | 对当前目标的作用 |
| --- | --- | --- |
| 前端 | React、TypeScript、Vite | 将库存卡片、筛选、详情和异常处理组织为独立组件 |
| 界面 | 项目自定义样式与设计变量，Lucide 图标 | 统一字体、间距、色彩和控件，避免直接套用管理后台皮肤 |
| 后端 | Python、FastAPI | 提供库存 API、接入已有 Python 工具及 Windows 主机操作 |
| 数据 | SQLite | 单服务管理库存与人工字段，浏览器通过 API 使用 |
| 封面 | 本地 FFmpeg 工具生成缓存图 | 读取 D 盘视频并提取封面，网页不需要传输原视频 |
| 后台执行 | 单个有界任务执行器，任务记录保存到 SQLite | 扫描与封面生成不阻塞请求；失败可见，重启后可恢复或重跑 |
| 服务管理 | WSL 中运行应用服务，具体启动方式实施时确定 | 为局域网提供一个访问入口 |

首版已采用上述技术组合，不引入独立数据库服务或分布式任务系统。

## 前后端边界与部署

前端只通过同源 API 获取和修改数据，不直接读取 D 盘、调用 Explorer 或维护权威库存。后端统一处理路径、编号、状态和任务。

开发时前端开发服务器代理 `/api` 到后端。生产时先构建前端，后端提供构建产物、封面资源和接口，浏览器访问一个地址。静态资源与 API 路由分开，页面刷新和深链接必须正常工作。

WSL 中保存代码、SQLite 和封面缓存；视频与脚本留在 D 盘。项目目录为 `/home/user/projects/script-workbench`。Windows 路径与 WSL 读取路径通过统一映射处理，不能把浏览器端路径字符串直接交给执行器。

本机采用 WSL NAT 网络，应用服务监听 `127.0.0.1:8789`。Windows 标准库网关提供本机 `http://localhost:8788/` 与局域网 `http://192.0.2.20:8787/` 两个入口，固定转发至该后端。本机入口验证 Host 与操作 Origin 后注入私有主机凭据；LAN 入口剥离凭据，后端也拒绝目录打开操作。后端校验数据库内已有目录，使用内部响应头将路径传给本机网关，网关剥离该头、复核 D 盘范围，再调用 Explorer，避免 WSL systemd 的 Windows interop 依赖。

## 后端模块

| 模块 | 职责 |
| --- | --- |
| 库存查询与编辑 | 提供搜索、筛选、详情与状态修改；返回分页和统计 |
| 扫描器 | 枚举配置目录，识别完整编号和素材，维护扫描结果 |
| 编号与关联 | 保留子编号、规范化 S29 与 S029、记录重复路径和历史未匹配项 |
| 历史导入 | 一次性导入本地历史快照，按完整编号导入发布状态 |
| 封面服务 | 提取与缓存封面，按视频变化刷新，记录失败原因 |
| 后台任务 | 序列化扫描任务、限制封面并发，记录进度与错误 |
| 主机能力 | 判断是否允许目录打开，并在支持时调用素材主机资源管理器 |
| 系统配置 | 保存库存根目录、扫描设置及路径映射 |

扫描器维护“发现了哪些文件”，人工编辑维护“作品的发布状态和信息”。分开更新这些字段，防止一次扫描覆盖用户填写内容。

库存扫描仅由网页“立即扫描”触发；服务启动、定时调度及目录变化均不自动创建扫描任务。手动任务在后台执行并持久化，关闭网页不影响任务。

已配置扫描根目录作为允许访问的范围，用户勾选的启用目录另外保存在 SQLite，不改变目录打开及预览功能原有的路径校验范围。设置页显式保存目录选择，使用修订号检测多客户端修改；提交扫描时将启用目录快照写入任务，服务恢复继续使用原任务范围。未选目录保留此前库存与素材记录，扫描及封面生成均跳过该目录。

任务不能只依赖请求完成后的临时内存回调。扫描和封面任务写入任务记录，启动时处理上次中断的任务；扫描幂等，封面能按输入文件变化重建。首版采用单应用进程与单任务调度实例，避免重复调度。

## 数据对象建议

| 对象 | 主要字段 |
| --- | --- |
| 库存作品 | 内部标识、完整规范编号、标题、待发布或已发布、备注、创建和更新时间 |
| 目录关联 | 作品标识、原始文件夹名、Windows 路径、WSL 读取路径、扫描根、可访问情况 |
| 素材 | 所属目录、相对路径、类型、大小、修改时间、脚本轴类型、视频探测信息 |
| 封面 | 视频标识、生成参数、源文件指纹、缓存位置、生成结果 |
| 库存问题 | 编号冲突、素材缺失、历史未匹配等类型、涉及路径、处理情况 |
| 后台任务 | 类型、目标、排队或运行等执行状态、开始和结束时间、结果或错误 |
| 历史资料 | 来源快照、完整编号、发布信息、匹配或待关联情况 |

库存作品只有两种发布状态。扫描可访问情况、后台任务执行状态和问题处理情况是系统信息，不能混入作品发布状态。

同编号多个路径通过目录关联和问题记录展示，不因冲突覆盖目录或复制作品。不同子编号独立维护。文件探测出的轴类型可展示，但不能据此自动选择最终发布版本。

## 接口建议

以下是实现方案的草案，不代表接口已经存在。

| 接口 | 用途 |
| --- | --- |
| `GET /api/works` | 搜索、发布状态筛选和分页 |
| `GET /api/works/{id}` | 获取作品、目录、素材和异常 |
| `PATCH /api/works/{id}` | 修改发布状态和允许人工维护的字段 |
| `GET /api/issues` | 查询编号冲突与未匹配资料 |
| `POST /api/scans` | 提交扫描，返回任务标识；已有扫描时复用或提示 |
| `GET /api/jobs/{id}` | 获取后台任务结果 |
| `GET /api/capabilities` | 返回当前访问端是否支持打开主机目录及原因 |
| `POST /api/works/{id}/open-folder` | 在支持的主机客户端打开已关联目录 |
| `GET /api/covers/{id}` | 返回缓存封面，支持浏览器缓存 |

目录打开必须在后端核实能力，不能相信前端自行声明“我是主机”。其他客户端返回不支持，不能触发主机资源管理器。识别机制及 WSL 到 Windows 的调用方式必须在部署环境中实测；未验证前不能宣称支持。接口接收目录关联标识，服务端解析已记录路径，不接收任意命令。

## 前端视觉方向

推荐“封面画廊”：左侧轻量导航，右侧内容区以作品封面为主。整体采用低饱和中性色、一个青绿色强调色、清晰的中文排版和充足留白。深浅主题都保持封面与文字的对比度。

美观来自稳定的封面比例、编号排版、统一的控件和信息层级。主背景与控件保持安静，色彩主要来自实际封面和发布状态。编号容易扫读，标题比技术字段更突出。

### 页面结构

- 库存：封面卡片为默认视图，搜索、发布状态筛选和立即刷新集中在顶部。
- 待处理：编号冲突、素材缺失和历史未匹配项，展示实际路径与处理方式。
- 扫描记录：最近任务、扫描结果与失败原因；不与作品发布状态混淆。
- 设置：目录、扫描规则等低频操作。

首版只实现已有需求对应的页面功能，不为视觉填充虚构分析图表或无来源统计。可保留目录视图作为高密度浏览方式，其优先级由视觉评审决定。

### 库存卡片

封面保持统一比例。卡片展示完整编号、作品标题和两种发布状态，必要时显示素材异常标记。路径和多轴文件清单在详情中展开，避免主列表拥挤。

状态同时使用文字与颜色表示。卡片点击展开作品详情，按钮操作不误触整张卡片。封面失败时使用统一占位，不令卡片高度变化。

### 作品详情

桌面端建议使用右侧详情面板，保留当前列表和筛选。展示较大封面、完整编号、素材清单、可修改的发布状态和打开文件夹操作。手机端改为单列详情，重要操作始终可见。

远程客户端在目录按钮附近明确显示不支持原因。状态保存提供进行中、成功和失败反馈；失败时保留原状态并提示，不把未写入数据当作成功。

### 视觉变量与交互

| 项目 | 建议 |
| --- | --- |
| 字体 | 中文系统无衬线字体；编号可使用等宽或等宽数字 |
| 内容字号 | 正文14至16px，辅助文字12px，重要标题按层级增加 |
| 颜色 | 中性背景、深色正文、青绿色主操作；待发布用暖色标记、已发布用绿色标记 |
| 间距 | 采用4与8px倍数，主区域保持24px左右留白 |
| 圆角 | 小控件8px，作品卡片与面板12至16px |
| 图标 | 统一 Lucide 线性图标，配合文字，不使用 emoji 作为功能图标 |
| 动效 | 悬停与反馈约150至200ms，详情展开约200ms；尊重减少动态效果设置 |
| 响应式 | 宽屏画廊、窄屏减少列数，手机单列或双列；工具栏换行而非横向溢出 |

## 视觉草图与验证范围

本轮将提供“封面画廊”和“紧凑目录”两种布局的可交互草图，搜索、筛选、作品详情和状态修改仅在草图内演示。封面使用抽象示意图，不读取或展示真实视频内容；数量和素材数据明确为演示。

草图不会调用实际扫描、修改库存状态或打开资源管理器。它用于选择前端方向，正式软件的接口、数据库、局域网可访问性和主机目录打开仍需开发及验证。

本轮通过本地 HTTP 预览检查了搜索、详情展开、发布状态修改和发布状态筛选；检查了桌面与320、375px窄屏布局以及深浅主题。检查期间的浏览器日志未出现错误或警告。目录版320px检查中，产品区域的内容宽度与可视宽度均为271px，没有产品区域的水平溢出。这些结果只覆盖草图，不代表真实库存服务已通过测试。
